HOW TO REUSE THIS PROCESS FOR OTHER APPS

1. Export that app's CURRENT Play declaration first. Keep an untouched copy.
   Confirm package/app identity; never copy another game's IDs or consent row.
2. Inventory the actual release SDK versions and every off-device path:
   account/guest auth, cloud gameplay, purchases, ads, analytics and crashes.
   Local-only game stats do not automatically belong in a data declaration.
3. Compare current code and provider disclosures. Combine all applicable paths
   for each type; do not use one optional SDK to cancel a required path elsewhere.
   Check dashboard integrations and opt-ins without enabling new processing.
4. Record each changed response with its evidence. Separate known corrections
   from uncertain provider behavior. Do not claim a feature is disabled merely
   because its setup banner, purchase key or analytics link is absent.
5. Validate CSV row identities, five columns, booleans, exclusivity and required
   follow-ups. Review the actual CSV values, not only the Console summary count.
6. Resolve A/B above for THIS app and create a separately named final copy.
   Importing overwrites existing Console answers: take a fresh backup first,
   inspect every affected type and the Preview, then have the owner approve
   submission. Re-export saved answers and compare to the intended final copy.
