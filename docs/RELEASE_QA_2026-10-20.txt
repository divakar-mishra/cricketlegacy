Important defect found by actual device testing
----------------------------------------------
The original optimization tests normalized only the root updatedAt. They did
not run a realistic save through synchronizeSchema14State before each backup.
Device testing exposed that this existing canonicalizer unconditionally set
premiumWallet.updatedAt to the save time even when coins/gems were unchanged.
This defeated the intentionally strict fingerprint's no-op detection.

Observed before fix: Manager slot 1 revisions advanced 15 -> 16 during initial
save, then through 20 during repeated save/backup actions. Remaining economic
benefits, flags/transaction markers and entitlements stayed unchanged; the
canonical premium-wallet clock alone changed within the paid-state evidence.
Do not describe those initial UI confirmations as successful deduplication.

After owner approval, schema14.ts now preserves a valid version1 wallet clock
when normalized coin/gem balances are identical. Missing/invalid canonical
state or actual balance changes update the clock. Inventory/focus and other
save changes still synchronize. The fingerprint still includes ALL nested
financial fields, timestamps, entitlements and purchase markers. No financial
data was removed from hashing and no save schema/server protocol changed.

Regression evidence: the new Player and Manager real-save/canonicalizer/sync
tests failed on the old implementation (four uploads instead of one). With
the new clock unit cases, the negative-control run had 10 failing assertions.
All pass after the fix. Real coin/gem changes must still upload; token and
purchase markers remain checked. Invalid timestamps, legacy initialization,
normalization, backwards clocks and unrelated resource changes are covered.
