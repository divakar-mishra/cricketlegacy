Consent and age behavior
------------------------
Existing age eligibility remains: unknown/under-13/India-teen/no-guardian or
failed age-storage gates do not initialize ad serving. Eligible teens outside
India retain TFUA=true, G-rated Google request configuration and NPA requests;
TFCD remains false because the app is not directed to under-13 children.
Do not silently change the Unity dashboard to child-directed or Mixed Audience.
Verify Unity content controls/creative suitability before activating this path;
Google's maximum-content-rating request alone does not certify Unity creatives.

UMP canRequestAds is permission to request an eligible ad, NOT proof that Unity
personalization is allowed. Unity receives privacy.consent=false by default.
Only an adult with current request permission, gdprApplies=1, consent for storage
and personalized-ad purposes 1/3/4, and a valid Additional Consent v1/v2 explicit
grant for Unity ATP 3234 can receive privacy.consent=true. A disclosed-only
provider is not a consent grant. Missing/wrong-typed/malformed/future signals,
teens, request denial and unsupported regional signals remain opted out.

The resolver does not decode raw TCF vendor strings or GPP to infer grants.
An otherwise valid TCF-only Unity grant (the dashboard displays GVL vendor 1549)
without supported Additional Consent therefore remains contextual-only. US and
other non-EU users also receive the conservative Unity opt-out by default. This
can reduce personalized Unity demand; it is not a promise of fill or revenue.
Google's existing adult UMP serving-mode selection is not changed.

privacy.consent is the single authoritative Unity consent key; Unity documents
that it overrides the older gdpr.consent key. user.nonbehavioral is also set
restrictively, but is not treated as proof of dashboard audience compliance.
Each metadata field is committed separately. No raw CMP strings are logged or
uploaded by the bridge. Native shared-preference changes reapply restrictions;
the listener unregisters when the RN module is invalidated.

Privacy editing immediately closes banner readiness, invalidates pending ad
requests and suspends Unity personalization. After the form, metadata is applied
again before readiness returns. Age changes/stale initializations cannot reopen
ads. Previously loading ads are discarded even if request permission later
returns or a declined choice still permits limited-ad requests.
