migrations in order against the correct project; compare remote migration

Auth -> Providers: configure only supported login providers. For Google OAuth,
configure the Google consent screen/client and the Supabase callback supplied
by that project. Auth -> URL Configuration: set the real public Site URL and
allow the EXACT mobile redirect produced by the app's auth configuration.

Do not guess a callback suffix from the app scheme alone. Test cancel, expiry,
retry, cold-start return and a browser already signed into a different account.
Official redirect reference:
https://supabase.com/docs/guides/auth/redirect-urls

Bind cloud reads/writes to the authenticated owner. Keep auth epoch checks so
old async work cannot write into the new account after a switch. Use revision
checks for concurrent saves and preserve paid balances/inventory during recovery.
Local saves must survive offline play. A failed upload must remain pending;
show success only after acknowledgement. Test conflicts and corrupt/old saves.

Optimization lessons from Cricket:
  - Coalesce equivalent queued sync requests for the same owner/auth epoch.
  - Reuse one validated identity within a bounded sync batch.
  - Skip unchanged snapshots only after checking the acknowledged remote state.
  - Preserve wallet timestamps when balances did not change.
  - Never exclude real financial/gameplay changes from the backup fingerprint.
These client changes reduce future work after adoption. They do not automatically
shrink existing database files or erase old backups. Measure database storage,
egress, reads/writes and active users separately; '15% resources' is not a metric
specific enough to extrapolate capacity. Pruning needs its own retention decision.

For deletion, authenticate server-side, delete only that owner's allowed data,
handle retries, and explain legally required retained evidence. Provide both
in-app access and a functioning public deletion route where required. Verify the
actual backend and operating process match the retention promises on the website.
Do not test deletion against the only copy of a real user's career.
