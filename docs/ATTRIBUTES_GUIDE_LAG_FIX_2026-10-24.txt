Source confirmed problems introduced/left in the QA26 guide flow:

  summary cards. Revealing that target intentionally skipped down the page.
- The next target wrapped the WHOLE attribute page, so the next guide step

  Delayed/overlapping results could therefore over-correct the same position.

  layout/reveal events could issue the same scrollTo command while pending.

  unrelated target registration/layout also invalidated the active measurement.

IMPLEMENTED
------------
1. Real top-to-bottom attribute targets:
   starting-level -> creation-difficulty -> attribute-budget -> attribute-plus
   -> attribute-controls -> creation-next.
   Setup cards, difficulty, summary and full allocation list now have distinct
   targets. The follow-up allocation target excludes earlier setup cards. The
   guide explains pathway, challenge and budget BEFORE revealing the real +.
   No point, pathway, role, difficulty or career outcome is chosen automatically.
2. GuideScrollView uses RN0.86's existing public innerViewRef and measureLayout
   against the actual native content View. No extra layout wrapper or dependency
   is added. Content-local y remains stable while scroll events arrive late;
   it is no longer reconstructed from window y plus optimistic offsets.
3. Coalesces reveal requests per animation frame, rejects superseded results,
   checks step/chapter scope and unmount lifetime, and retries only on a real
   layout/step request rather than recursively spinning after measurement failure.
4. Actual native offset and pending requested offset are separate. Identical
   pending corrections are deduplicated; no scroll command is sent if already
   in place. Unchanged viewport/content dimensions do not re-reveal a target.
5. Normal scroll frames shift the cached spotlight by actual scroll delta,
   instead of measuring native root/target views on every frame. Current-step
   bounds and tall-list scrolling remain; fixed coach actions/Skip still work.
6. Guided form pages remount the native scroller on scrollResetKey, avoiding a
   competing imperative scroll-to-top effect. Parent form state remains outside
   the scroller; ordinary unguided screen scroll-reset behavior is retained.
7. Only a Stepper with guideIncreaseId mounts a GuideTarget. Inactive target
   registration/layout no longer forces active-target measurement/reveal work.
   The React Compiler lint constraint is satisfied, not disabled/suppressed.
