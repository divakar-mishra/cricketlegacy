   Android keeps the existing static configuration. Distribution keeps
   com.coverdrive.cricket; simulator uses com.coverdrive.cricket.simulator.

   A missing/placeholder distribution App ID raises a clear configuration error.

   iOS unit configuration leaves its ads unavailable before UMP/initialization.
   Initial iOS requests are contextual; no ATT prompt/IDFA tracking is added.
   There is no Unity native iOS adapter/bridge in this port. Android Unity
   configuration and its published Play AAB are not modified by this work.

3. Apple sign-in via Supabase browser OAuth with the existing exact mobile
   callback, provider verification, single-flight guard and persisted identity.
   iOS Account offers a black/white Apple-branded button alongside Google.
   Apple sessions rehydrate as Apple, not mislabeled Google. Canceled/expired/
   foreign callbacks cannot grant local auth success or purchase fulfillment.
   This is the browser/Services-ID route, not native Apple ID-token login.
   No Apple private keys or client secrets belong in the mobile app.

4. Apple's system review request after the existing five-completed-match
   eligibility and safe-screen/modal-queue checks. Installation-local durable
   history prevents duplicate calls across hubs. No custom iOS rating pre-prompt.
   Apple's quota decides whether a dialog appears; request completion is not
   evidence of a displayed/submitted review.

5. Account backup copy now supports provider-neutral sign-in. Existing owner/
   epoch/revision/financial preservation checks remain the recovery authority.
   Firebase native packages/plugins are excluded on iOS while its platform
   service setup is missing, and inactive diagnostic toggles are hidden there.
   Android retains its existing optional Firebase implementation. This is an
   intentional unavailable integration, not fake Firebase configuration.

6. EAS ios-simulator and ios-production profiles, explicit iOS target for the
   local ios command, a distribution configuration gate, and .env.ios.example.
   The store build gate now applies legal checks to ios-production as well.
   All owner placeholders stay out of actual simulator service identities.

7. Reproducible, allowlisted staging script:
     npm run ios:prepare:simulator
   It refreshes output/ios-simulator/workspace from current source, excludes
   private environment files and preserves the previously requested mute in
   staged audio only. Generated ios/ is excluded from source archives, so
   source config must reproduce native configuration during future builds.
