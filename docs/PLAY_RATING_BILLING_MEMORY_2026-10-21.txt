Rating implementation
---------------------
src/components/PlayRatingPrompt.tsx: a dismissible, theme-based, compact-safe
modal. It runs only on focused, foreground Android career hubs, after settings
hydrate/onboarding and five completed matches in the existing device counter.
It does not inspect whether those matches were won, lost or drawn. The existing
counter is already driven by canonical match commits/daily challenge settlement;
no new progression or reward path was added.

Uses the existing global prompt-priority modal queue; explicit hub guards defer
for guides, achievements, rewards, newspapers, contracts, offers and simulation.
The Player hub also waits for its existing interstitial attempt and starter
lookup. The ad policy/caps/units are not changed. No extra native blur is added.

Actions: Rate on Google Play / Not now. Android Back and outside taps dismiss.
src/services/storeReview.ts now records sr:play-prompt:v1 before showing the
invitation. This is installation-local, survives ordinary updates/settings
reset, and is not added to careers or Supabase payloads. Existing sr:lastPrompt
history is honored; corrupt/unreadable history fails closed. Simultaneous
retained hubs cannot both claim an invitation. It never repeats weekly or
changes based on whether a rating was submitted (the app cannot observe that).

The explicit CTA opens market://details?id=com.coverdrive.cricket&showAllReviews=true,
then the equivalent public HTTPS URL if necessary. It does not call Google's
quota-limited native review API from a button. Failed links leave an inline
error and Not now remains available. No stars, currency or gameplay incentive
is requested/granted. Settings has the same voluntary Play link for later use.
The old win-only native review request in careerStore was removed.
