CONFIRMED DEFECTS AND FIXES
--------------------------
1. Storage-pressure retry leak — persistence reliability risk
   src/storage/storage.ts:setJSON
   Large saves stage a new chunk generation before atomically publishing its
   manifest. Failed publication previously left those uncommitted chunks behind.
   Three 600k-character retries reproduced nine orphan rows (about 1.8M retained
   characters). The last good value remained readable; no corruption is claimed.
   Repeated retries could consume more capacity exactly when storage was full.
   FIX: reclaim only the failing write's staged generation. Preserve committed
   chunks when a bridge rejection occurs after commit, or commit cannot safely
   be checked. Cleanup failure must not mask the original write error.
   Tests cover small/large previous values, partial batch failure, three retries,
   unrelated saves, successful later retry, ambiguous committed writes and
   cleanup/read failures. No broad garbage collection or save migration added.
   Limits: cannot guarantee cleanup after OS process death or a native cleanup
   failure; existing orphan generations are not blindly swept from user data.

2. False failed-creation message / duplicate-career retry — both modes
   src/screens/PlayerCreationScreen.tsx:create
   src/screens/TeamSelectScreen.tsx:create
   The first career write could succeed, followed by failure of the optional
   last-played pointer. The UI then incorrectly said the career was not created.
   Retrying reproduced a second save in another slot in Player and Manager.
   FIX: a confirmed career write remains successful even if resume metadata
   fails; activate it and open its Home. Actual first-write failure still blocks
   activation and retains a retry. Same-frame duplicate guards are preserved.
   This is a fix for the demonstrated optional-pointer failure, not a blanket
   guarantee that every possible native storage failure is unambiguous.

3. Delayed match-ad reward could credit another career
   src/screens/MatchScreen.tsx:result reward callback
   src/state/careerStore.ts:grantAdReward
   Start result-screen rewarded loading in Player A, leave and open Manager B,
   complete the old ad: B incorrectly received A's 100-coin bonus in the repro.
   FIX: capture the requesting save ID before awaiting the provider and reject
   delivery if a different career is active. Reject non-finite amounts before
   consuming a transaction. Same-save duplicate delivery remains idempotent.
   An interrupted request cannot spend another save's claim. A rejected call
   does not mark either save's transaction as claimed; automatic delivery to an
   inactive career is not promised. This matches the existing energy-ad cross-save
   safety policy. Native ad errors now show a retry message
   and always release the button's busy guard rather than reject unhandled.

4. Concurrent Home interstitials bypassed the loading-time frequency check
   src/services/ads.ts:maybeShowInterstitial
   Two concurrent requests read identical old history and both created native
   ads. The new test failed with two creations where one was expected.
   FIX: synchronously reserve the Home request before any storage/consent/network
   await; release in finally, including no-fill/error and skipped/capped paths.

5. Failed interstitial-history persistence bypassed the in-memory spacing limit
   src/services/ads.ts:maybeShowInterstitial
   With a 20-minute-old stored timestamp, an ad was shown but history writing
   failed. The next call preferred the stale stored timestamp over the newer
   in-memory value and created another ad immediately. Reproduced by test.
   FIX: use the newer of in-memory and stored timestamps. The approved four/hour
   and 15-minute policy is unchanged; invalid non-array history is ignored safely.
   A process restart cannot recover an ad timestamp the device never persisted.

6. Loading interstitial had no navigation/current-VIP revalidation
   src/screens/CareerHubScreen.tsx:focus effect
   src/services/ads.ts:showInterstitial/showRealInterstitial
   Source inspection confirmed that eligibility was captured only at request
   time, while actual presentation happened later. Leaving Home or obtaining
   ad removal during loading did not invalidate that request.
   FIX/HARDENING: revalidate focus, exact career identity and current ad-removal
   entitlement before loading/presentation. Discard a stale loaded ad without
   showing it or consuming the frequency cap. Controlled provider tests cover
   all three eligibility changes; existing age/privacy revision guards remain.

No changes to match odds, training/energy values, prices, product benefits,
selection rules, fixtures, saved-state schema, native code, provider credentials,
store metadata, Android/iOS build profiles or iOS-specific configuration.
